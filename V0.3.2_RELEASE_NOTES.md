# IPTV Merge Manager v0.3.2 Release Notes

## HLS Compatibility & Resilience

v0.3.2 addresses Jellyfin/FFmpeg live-TV failures where a provider changes from ordinary `.ts` HLS segments to extensionless `/v1/segment/...` media URLs at an `#EXT-X-DISCONTINUITY` or ad boundary.

### Primary fix

When compatibility mode sees an extensionless or unsupported media segment URL, it publishes a short-lived local alias ending in a safe extension, for example:

```text
http://IPTVMM:8080/hls/channel/174/segment/8d7a...c9.ts
```

Jellyfin/FFmpeg accepts the `.ts` path. IPTV Merge Manager then returns an HTTP redirect to the provider's real segment URL. The segment bytes still move directly between Jellyfin and the provider/CDN.

### HLS modes

- **Direct** — no HLS playlist processing.
- **Playlist Compatibility** — adaptive choices remain available; child playlists are rewritten for compatibility.
- **Fixed Variant + Compatibility** — one adaptive rendition is selected, then compatibility rewriting is applied. This is the recommended mode for the reproduced Jellyfin issue.

### Configuration hierarchy

Settings can inherit in this order:

```text
Global -> Source -> Channel
```

Existing v0.3.1 databases are migrated without changing expected behavior:

- Variant Lock ON -> Fixed Variant + Compatibility
- Variant Lock OFF -> Direct

### Diagnostics

New counters/events include:

- extensionless segment fixes
- segment redirects
- HLS discontinuities
- CDN host changes
- child-playlist requests
- variant master re-resolves
- failures and bypasses

Per-channel diagnostics keep only a bounded recent event history.

### Resource behavior

v0.3.2 does not add FFmpeg, transcoding, media buffering, or a full segment relay. Playlist payloads remain capped at 512 KiB, token registries are bounded and expiring, and the one-worker/disk-backed v0.3 architecture is retained.

# IPTV Merge Manager v0.4.0 — Integrated Stream Stabilization

v0.4.0 integrates the experimental IPTV Stream Stabilizer directly into IPTV Merge Manager. Jellyfin continues to consume the normal `master.m3u` and `master.xml`; IPTV Merge Manager decides per channel whether playback is direct/protected or routed through an on-demand FFmpeg normalization worker.

## New playback architecture

The recommended configuration for troublesome FAST/SSAI sources is:

```text
Provider / FAST HLS
        ↓
IPTV Merge Manager Protected acquisition
        ↓
Integrated Stabilizer — Remux
        ↓
Timestamp-normalized local HLS
        ↓
Jellyfin
```

Acquisition and stabilization are independent controls. A source can therefore use Direct, Compatibility, Fixed, or Protected acquisition and separately choose whether its output should be stabilized.

## Source-level stabilization

Every source now has a Stabilization default:

- **Off** — no stabilization.
- **Stabilized Remux** — FFmpeg remuxes the HLS stream with stream-copy while allowing timestamp-discontinuity correction.
- **Full Software Transcode** — FFmpeg decodes/re-encodes H.264/AAC and regenerates timestamps as a stronger fallback.
- **Inherit Global** — use the global stabilizer default.

Existing v0.3.4 sources migrate with Stabilization **Off**, so upgrading does not change existing playback behavior until stabilization is explicitly enabled.

## Per-channel overrides

Channels can inherit the source/global setting or override it with:

- Off
- Stabilized Remux
- Full Software Transcode

Bulk actions are provided for the same choices.

## Stabilized Remux

Remux is the recommended first option for Samsung TV Plus / FAST / SSAI streams with ad-boundary or timestamp issues. The worker command intentionally:

- does **not** use `-copyts`;
- does **not** use `-re`;
- uses configurable `-dts_delta_threshold` (default `1.0` second);
- uses `-c:v copy -c:a copy` so video/audio are not decoded or re-encoded;
- outputs a rolling MPEG-TS HLS stream for Jellyfin.

This keeps CPU usage low while giving FFmpeg an opportunity to normalize HLS/MPEG-TS timestamp discontinuities before Jellyfin receives the stream.

## Full Software Transcode

For feeds that remain unstable after remux normalization, Full Software Transcode adds:

- `-fflags +genpts`;
- libx264 video encoding;
- AAC audio encoding;
- `aresample=async=1:first_pts=0`;
- configurable x264 preset, CRF, and audio bitrate.

This mode is intentionally software-based so it does not consume the GPU that Jellyfin may need for client transcoding.

## On-demand worker lifecycle

A configured source can contain hundreds of stabilized channels without hundreds of FFmpeg processes. A worker starts only when Jellyfin requests:

```text
/stabilized/channel/<channel-id>/index.m3u8
```

The same per-channel worker/output is shared by all viewers requesting that channel. Default lifecycle controls:

- 2 output segments required before the playlist is returned;
- 15-second startup timeout;
- 8-second output-stall watchdog;
- automatic restart on output stall;
- 60-second idle shutdown;
- maximum 12 simultaneous stabilizer workers.

## Diagnostics

The dashboard now reports:

- configured stabilized channels;
- active/known workers;
- restarts;
- detected output stalls;
- worker errors.

Per-channel Stabilizer Diagnostics show:

- effective stabilization mode;
- acquisition mode feeding the worker;
- running/idle state and PID;
- segment count and output age;
- starts/restarts/stalls;
- last restart reason and error;
- exact FFmpeg command after the worker has started.

Worker logs are stored under:

```text
/app/data/logs/stabilizer/
```

Rolling output is stored under:

```text
/app/data/cache/stabilized/
```

## Docker/CasaOS

FFmpeg is now installed inside the IPTV Merge Manager image. No GPU device mapping is required for Stabilized Remux or the default Full Software Transcode mode.

The Docker/CasaOS application remains a single service on port `8080`. Because v0.4.0 adds FFmpeg to the image, source-build upgrades must **rebuild/recreate the container** after applying the v0.4.0 files (for example, `docker compose up -d --build`). GHCR/CasaOS installs should pull/recreate the `0.4.0` image.

## Upgrade notes

The database migration is additive:

- adds `sources.stabilizer_mode` with default `off`;
- adds nullable `channels.stabilizer_mode` for inheritance/overrides;
- adds global stabilizer settings to `app_settings`.

Existing HLS Protected/Fixed/Compatibility/Direct selections are preserved.

For a Samsung TV Plus-style source, the initial recommended source configuration is:

```text
Acquisition:    Protected
Stabilization:  Stabilized Remux
```

Use Full Software Transcode only for channels that still fail in Remux mode.

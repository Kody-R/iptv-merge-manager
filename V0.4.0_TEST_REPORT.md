# IPTV Merge Manager v0.4.0 Test Report

## Automated unit/regression suite

Command:

```bash
PYTHONPATH=. python -m unittest discover -s tests -v
```

Result:

```text
Ran 26 tests
OK
```

Coverage includes all v0.3.4 HLS/protected-playback tests plus new v0.4.0 tests for:

- stabilization inheritance hierarchy;
- Remux command construction;
- deliberate absence of `-copyts` and `-re`;
- `-dts_delta_threshold` use;
- Protected acquisition as the internal input to a stabilized worker;
- Full Software Transcode command construction with `+genpts`, libx264, AAC, and async audio resampling;
- additive v0.4.0 database schema/settings;
- source-level Remux causing `master.m3u` to publish `/stabilized/channel/...`;
- per-channel Off overriding a stabilized source and falling back to the HLS acquisition route.

## v0.3.4 → v0.4.0 database migration test

A database was created using the actual v0.3.4 `db.py`, populated with a Protected source/channel, and then opened/migrated with v0.4.0.

Verified:

```text
source stabilizer_mode = off
channel stabilizer_mode = NULL (inherit)
source hls_mode = protected
channel hls_mode = protected
global stabilizer_default_mode = off
```

This confirms the upgrade is additive and does not automatically reroute existing channels through FFmpeg.

## Functional FFmpeg Remux smoke test

A synthetic 640×360 H.264/AAC HLS source was generated with FFmpeg and served over local HTTP. The v0.4.0 Stabilized Remux command builder was then used to consume and re-publish it.

Result:

```text
functional remux smoke: PASS
output playlist: created
output MPEG-TS segments: 3
ffprobe video: H.264 640x360
ffprobe audio: AAC
```

The generated command used stream copy and contained no `-copyts` or `-re`.

8. Discontinuity diagnostics generated with the extensionless-segment case.
9. Normal `.ts` segments remain direct even in compatibility mode.
10. HLS global/source/channel hierarchy plus v0.3.2 DB/output fields.
11. v0.3.1 boolean Variant Lock migration to explicit Direct/Fixed modes.
12. Guarded synthetic-segment relay successfully streams media bytes and closes cleanly.
13. A provider that returns headers but never produces media is retried once and then fails within bounded deadlines.
14. A failed segment refreshes its upstream media playlist and can retry a changed URL only when it represents the exact same HLS media sequence.
15. A segment that produces media and then goes idle is terminated by the stale-segment read watchdog instead of hanging indefinitely.
16. A downstream disconnect cancels and cleans up the guarded upstream relay.

## Guarded-relay behavior exercised

The v0.3.3 tests use local deterministic HTTP servers rather than an external IPTV provider. They specifically exercise:

- successful binary segment relay;
- first-media stall before any bytes are emitted;
- bounded retry accounting;
- same-media-sequence URL recovery from a refreshed playlist;
- mid-segment read-idle timeout;
- downstream cancellation cleanup;
- preservation of direct URLs for recognized `.ts` segments.

## Runtime limitation of this build environment

Docker/Podman is not installed in the build environment, so an actual container image build was not executed here. APScheduler is also not installed in the host Python environment, so the complete FastAPI route table was smoke-tested with that dependency stubbed; the Docker image installs the pinned `APScheduler==3.11.0` dependency from `requirements.txt`.

Outbound live-provider testing is not available from this environment. The final real-world validation remains the Jellyfin commercial/ad-break stream that reproduced the v0.3.2 indefinite FFmpeg stall.

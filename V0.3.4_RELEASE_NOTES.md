# IPTV Merge Manager v0.3.4 Release Notes

Release date: 2026-08-14

## Focus

v0.3.4 is a reliability-first HLS release aimed at streams that remain healthy during normal programming but freeze around commercial breaks, SSAI discontinuities, or CDN transitions.

The key change is **Protected Playback**. Protected mode no longer streams an upstream media response directly into Jellyfin while that response is still in progress. IPTV Merge Manager downloads the complete segment to a temporary disk file, validates completion, atomically renames the file into the protected cache, and only then serves it to Jellyfin.

```text
upstream provider/CDN
        |
        v
 temporary .part file
        |
  complete + validate
        |
   atomic rename
        |
        v
      Jellyfin
```

A provider can therefore stall or terminate a segment without leaving Jellyfin FFmpeg attached to a half-open IPTVMM response.

## Protected Playback behavior

Protected mode:

- locks adaptive HLS to the configured maximum rendition, like Fixed mode;
- rewrites every media segment through IPTV Merge Manager, including ordinary `.ts` URLs;
- uses disk-backed segment storage rather than whole-segment RAM buffering;
- prefetches the newest 2 segments by default;
- de-duplicates simultaneous requests for the same segment with a single in-flight download;
- reuses completed files from the protected cache;
- applies a 15-second whole-segment deadline by default;
- retries up to 2 bounded attempts by default using fresh HTTP connections;
- refreshes the source media playlist between attempts and can recover a changed URL for the exact same HLS media sequence;
- discards partial `.part` files on any failed attempt;
- returns a bounded reload/skip response after final failure instead of keeping the segment request open indefinitely;
- cleans stale protected cache files and enforces a configurable cache ceiling.

## Default Protected settings

| Setting | Default |
|---|---:|
| Prefetch depth | 2 segments |
| Whole-segment deadline | 15 seconds |
| Attempts | 2 |
| Skip/reload failed segment | Enabled |
| Disk cache ceiling | 512 MB |
| Cache retention | 180 seconds |
| Per-segment safety ceiling | 64 MB |

These settings are available in the HLS Playback Protection panel. The 64 MB per-segment safety ceiling is controlled by `HLS_PROTECTED_MAX_SEGMENT_BYTES` if a provider requires unusually large segments.

## Upgrade migration

On the first v0.3.4 database initialization, existing v0.3.3 selections explicitly configured as **Fixed Variant + Compatibility** are migrated to **Protected Playback**:

- per-channel Fixed mode → Protected;
- per-source Fixed default → Protected;
- global Fixed default → Protected.

The migration runs once. Direct and Compatibility modes are not changed. Fixed mode remains available and can be selected again after the upgrade when direct-to-CDN media segment delivery is preferred.

## Dashboard/diagnostics additions

New counters include:

- Protected Downloads
- Protected Cache Hits
- Protected Prefetches
- Protected Retries
- Protected Timeouts
- Protected Failures
- Protected Skips
- Protected Completed
- Protected Bytes
- Protected Invalid/Incomplete Segments

Per-channel HLS diagnostics include the corresponding channel-specific counters and recent recovery events.

## Resource design

v0.3.4 intentionally trades some network and disk I/O for continuity. IPTV Merge Manager still does not transcode media and still runs one Uvicorn worker. Completed media segments live in `/app/data/cache/hls-segments`, so the large payloads do not need to remain resident in Python memory.

The design target is low-to-medium memory consumption, with normal deployments expected to remain well below 1 GB RAM unless other source-refresh/XMLTV workload or unusually high concurrency dominates the container.

## Recommended first test

For a channel that previously froze at commercial breaks:

1. Upgrade to v0.3.4.
2. Confirm the channel shows **Protected** in the Channel Browser. Existing v0.3.3 Fixed channels should migrate automatically.
3. Start with a 720p maximum quality cap.
4. Leave Protected defaults at 2-segment prefetch, 15-second deadline, 2 attempts, skip/reload enabled, 512 MB cache, and 180-second retention.
5. Let the same channel run through several commercial breaks.
6. If a failure occurs, collect the Jellyfin FFmpeg log and the channel's IPTVMM HLS Diagnostics panel. The new Protected counters make it possible to distinguish upstream timeout, successful retry, cache recovery, and final bounded skip.

## Upgrade from an existing repository checkout

Extract the upgrade ZIP over the repository root:

```bash
unzip -o iptv-merge-manager-v0.3.4_upgrade.zip

docker compose down
docker compose up -d --build
```

The persistent `data/` and `output/` directories are not included in the upgrade ZIP and are not replaced.
